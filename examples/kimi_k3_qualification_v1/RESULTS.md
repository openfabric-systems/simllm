## Dependency mechanism and independent arithmetic

Each expert layer sends the same input to routed and shared branches. Both
outputs must arrive before their sum becomes the layer result. The shared
branch has two parallel input projections, an activation and an output
projection: four visits but three sequential regions. A separate logical
addition follows both branches. This does not imply a separately launched
physical add kernel or the same ordering on native framework streams.

For ordinary service `O=1000 ps`, shared service `S` and final-add service `J`,
the independent dependency-depth expression is

`D = O*(4 + 3*93 + 6*69 + A*24 + 3) + 92*(max(9*O, 3*S) + J)`.

`A=8` for prefill and `A=10` for decode. The outside-expert contributions are
892,000 and 940,000 ps. All six settings below run through both frameworks.

| Shared service S (ps) | Final addition J (ps) | Prefill depth (ps) | Decode depth (ps) |
|---:|---:|---:|---:|
| 1,000 | 1,000 | 1,812,000 | 1,860,000 |
| 1,000 | 2,000 | 1,904,000 | 1,952,000 |
| 3,000 | 1,000 | 1,812,000 | 1,860,000 |
| 3,000 | 2,000 | 1,904,000 | 1,952,000 |
| 10,000 | 1,000 | 3,744,000 | 3,792,000 |
| 10,000 | 2,000 | 3,836,000 | 3,884,000 |

The dependency sum is a completion floor; summing all operation services is
a serial ceiling. Every cell lies within these logical bounds and matches
its exact dependency oracle. Doubling final-add service adds exactly 92,000
ps. Increasing shared service changes completion only after the shared branch
overtakes the nine-region routed branch. These checks identify both the join
and the maximum operator; a fitted whole-step constant cannot substitute.

All 92 branch parent sets, shared forks, additions and residual successors
are checked individually. Every addition reaches the language head. All 24
latent-attention cache commits are absent from prefill attention ancestry and
required in decode ancestry. The completion frontier contains exactly the
head and those original-index cache commits. Seven dependency corruptions per
framework preserve visit counts but fail their owning causal guards.

## State, packing and end-to-end synthetic checks

Three independent checks bound the interpretation. First, packed routed
weights contain 33,030,144 values per expert: half a byte per value plus one
scale byte per 32 values gives exactly 17,547,264 encoded bytes per expert.
This is checkpoint payload accounting, not bytes read by one decode step.

Second, retained Kimi Delta Attention state uses 434,110,464 recurrent bytes
and 15,261,696 convolution-history bytes per sequence, totaling 449,372,160.
The 24 latent-attention layers retain 27,648 bytes per cached token. Batch and
context sweeps preserve the separate state terms and their expected scaling.
Neither storage capacity nor logical FLOPs supply a measured service duration.

Third, the same graph reaches the supported completion-event and request
metric chain under explicit synthetic service. Let `P` be prompt tokens and
`c` be the assigned picoseconds per logical visit per new token:

`TTFT = 3244*P*c`, `TPOT = 3268*c`, `JCT = 3244*P*c + 2*3268*c`.

Time to first token (TTFT), time per output token (TPOT) and job completion
time (JCT) follow these relations in all eight cells: both frameworks,
`P` in `{1,4}` and `c` in `{1000,2000}`. At `P=1,c=1000`, they are
3,244,000, 3,268,000 and 9,780,000 ps. Doubling assigned service doubles all
three. These deliberately arbitrary operator costs exercise causality and
reduction; they do not represent K3 GPU speed.

## Reproduction

Configure the native interpreters, exact config-only checkpoint, selected
framework source snapshot, legacy checkpoints and retained historical raw
evidence through the local ignored environment. The external input hashes are
frozen; an absent historical evidence-name manifest rejects instead of silently
reducing coverage. Select a fresh output directory.

```bash
python -m examples.kimi_k3_qualification_v1.run_study \
  --vllm-python "$SIMLLM_VLLM_PYTHON" \
  --sglang-python "$SIMLLM_SGLANG_PYTHON" \
  --checkpoint-root "$SIMLLM_K3_CHECKPOINT_ROOT" \
  --source-root "$SIMLLM_K3_SOURCE_ROOT" \
  --legacy-checkpoints "$SIMLLM_K3_LEGACY_CHECKPOINTS" \
  --historical-root "$SIMLLM_K3_HISTORICAL_ROOT" \
  --output-root "$SIMLLM_K3_QUALIFICATION_OUTPUT"
```
